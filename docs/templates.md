# Template files

Every file in a template folder, except the config and anything in
[`ignore`](configuration.md#ignore), is a template. It is rendered with the
[Velocity Template Language](https://velocity.apache.org/engine/1.7/user-guide.html)
and written to the destination at the same relative path.

## File and folder names

Names can contain variables:

```text
scaffolding/page/${NAME}/List${PLURAL_NAME}.tsx   ->   src/pages/Tank/ListTanks.tsx
scaffolding/page/__tests__/${NAME}.test.tsx       ->   src/pages/Tank/__tests__/Tank.test.tsx
```

Files go inside a folder named after `NAME` unless the config sets
`createNameDir: false`.

## Velocity in five minutes

**Variables.** `$NAME` or `${NAME}`. Use the braces when text follows directly:
`${NAME}Props`. Properties and JavaScript methods work: `$endpoint.name`,
`${NAME.toLowerCase()}`, `$FIELDS.length`.

**Missing variables are left as written.** `$TYPO` is output as `$TYPO`, so a
misspelled variable shows up in the generated file. `$!TYPO` outputs nothing
instead.

**Escaping.** `\$NAME` outputs `$NAME`, for code that uses `$` itself, such as
template literals: `` `Hello \${user}` ``.

**Conditions.**

```text
#if($WITH_TESTS && $STYLE == 'css')
...
#elseif($STYLE == 'tailwind')
...
#else
...
#end
```

**Loops.** `$foreach.index` (from 0) and `$foreach.hasNext` are available inside.

```text
export interface I${NAME} {
#foreach($field in $FIELDS)
  $field.name: $field.type;
#end
}

export const COLUMNS = [#foreach($c in $COLUMNS)'$c'#if($foreach.hasNext), #end#end];
```

**Setting variables.**

```text
#set($PROPS = "I${NAME}Props")
export const ${NAME} = (props: $PROPS) => ...
```

**Template macros.** Define reusable snippets in the template itself:

```text
#macro(field $name $type)
  $name: $type;
#end
#field('id' 'number')
#field('label' 'string')
```

**Comments.** `## to the end of the line` and `#* across lines *#` are not output.
A `##` comment also removes the line break at the end of its line.

### Line breaks after directives

A line that ends with a directive, such as `#end`, a macro call or a `##` comment,
loses its line break:

```text
// #upperFirst($NAME)
// next line
```

renders as `// Tank// next line`. Directives on lines of their own (like the `#if`,
`#foreach` and `#end` lines above) are fine. When a macro call ends a line, add
`$!{nothing}` after it to keep the line break:

```text
// #upperFirst($NAME)$!{nothing}
// next line
```

## Macros

Functions from the config's `macros` are called like Velocity macros, and whatever
they return is inserted:

```ts
// scaffolding.config.ts
macros: {
  upperFirst: (s: string) => s.charAt(0).toUpperCase() + s.slice(1),
  names: (items: { name: string }[]) => items.map(i => `'${i.name}'`).join(', '),
},
```

```text
const label = '#upperFirst($NAME)';
const fields = [#names($FIELDS)];
```

Arguments can be any variable, including objects and arrays. Macros can also be a
function of the [context](configuration.md#functions-and-their-context), for macros
that need the answers or other variables:

```ts
macros: ({ variables }) => ({
  apiPath: (endpoint: string) => `${variables.API_ROOT}/${endpoint}`,
}),
```

For logic that is more than a line or two, a variable computed in the config is
usually easier to read than a macro.

## Includes

A line containing `#include(fileHeader.ts)` is replaced, as a whole, by
`scaffolding/_includes/fileHeader.ts`. The included file is rendered with the same
variables, and can include other files. Paths are relative to `_includes`.

```text
#include(fileHeader.ts)
import { ReactElement } from 'react';
```

`scaffolding/_includes/fileHeader.ts`:

```text
/**
 * Generated by the $TEMPLATE_NAME template (v$TEMPLATE_VERSION) for $USERNAME.
 */
```

An include that includes itself, directly or through other files, is reported as an
error.

## Stripping lines

Lines matching the config's [`stripLines`](configuration.md#striplines) are removed
before rendering, from templates and included files. Use them for comments meant for
template authors, and for code that keeps the template valid in your editor.

## Line endings

Templates can use LF or CRLF line endings. Each generated file keeps the line endings
of its template.

## When a file fails

If a template has a syntax error or a macro throws, that file is reported as
`failed`, the other files are still generated, and the run exits with code 1.

```text
  created  src/pages/Tank/ListTanks.tsx
  failed   src/pages/Tank/EditTank.tsx: Parse error on line 12: ...
```

Use `--dryRun` while writing a template to see the output without writing files,
and `--debug` to print every variable.
